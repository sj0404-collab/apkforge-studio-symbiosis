# Что было сломано в Symbiosis

Отчёт по репозиторию `sj0404-collab/symbiosis`. Каждый пункт: симптом → причина
(с файлом и строкой) → как проверено. Там, где причина не доказана, так и
написано.

---

## 1. «Из сотен nsz/nsp/xci видит одну игру»

**Симптом.** Библиотека на телефоне: один-два тайла при папке с сотнями файлов.

**Причины — их три, и они складываются.**

### 1.1 Сжатые образы не существовали для библиотеки

`patch/android/utils/GameHelper.kt`, `addGamesRecursive`:

```kotlin
if (Game.extensions.contains(extension) || GameFormats.isLaunchable(filename)) {
    val game = getGame(it.uri, true, false)
    if (game != null) games.add(game)
}
```

`GameFormats.LAUNCHABLE` — это `xci, nsp, nca, nro, nso, kip`. `nsz`, `xcz`,
`ncz` в него не входят, и это правильно: Eden не умеет zstd. Неправильно то,
что файл после этого **исчезал** — ни строки, ни причины, ни счётчика. В дампе,
где 200 из 210 файлов сжаты, библиотека выглядит почти пустой.

Сканер папки (`GameFolderScanner`) при этом знал про сжатые (`SHOWABLE_EXTENSIONS`)
и показывал их в счётчике. Два ответа на один вопрос.

**Стало.** `LibraryIndex.isWanted()` — одно правило на импортёр, сканер и панель.
Сжатый файл попадает в список с причиной «сжатый образ · сначала „Распаковать“
во вкладке Конвертер», на карточке — бейдж, по нажатию — кнопка, которая
ставит именно этот файл в очередь конвертера (`convertPath`).

### 1.2 Один файл без точки обрывал весь обход

`GameHelper.getGame()`:

```kotlin
programId = name.substring(0, name.lastIndexOf("."))
```

Для файла `main` (распакованный дамп, `loader.cpp` считает такое имя образом)
`lastIndexOf('.')` возвращает `-1`, и `substring(0, -1)` бросает
`StringIndexOutOfBoundsException`. Исключение уходит из `addGamesRecursive` в
`getGames()`, то есть **весь обход прекращается** на этом файле; в кэш попадает
только то, что успели прочитать. Ровно «видит одну игру».

**Стало.** `name.substringBeforeLast('.', name).ifBlank { name }`, плюс каждый
`getGame()` обёрнут в `runCatching` — один битый файл больше не стоит библиотеки,
он попадает в отчёт как «ядро не прочитало заголовок».

### 1.3 Потолок обхода 400 каталогов

`GameFolderScanner.MAX_DIRECTORIES = 400`. Дамп «одна папка на игру» на 500 игр
упирается в него и **молча** обрывается: счётчик показывает 400, хвост алфавита
пропадает целиком.

**Стало.** 20 000 каталогов и бюджет 25 секунд на обход (`SCAN_BUDGET_MS`):
защита от зависания осталась, а обрыв на середине библиотеки — нет.

### 1.4 Обновления и DLC выдавали себя за игры

Каждый `[v65536][UPD].nsp` и каждый `[DLC]` — отдельная запись. 12 игр с
обновлениями и DLC — это 40 «игр» в списке и одновременно «одна игра» в
карусели, если список отфильтрован.

**Стало.** `LibraryIndex` понимает роль файла по Title ID (`…000` — база,
`…800` — обновление, `…001`+ — DLC) и по тегам `[UPD]`/`[DLC]`. Панель рисует
бейдж «обновление»/«DLC», а сводка считает их отдельно: «742 файлов ·
120 игр · 120 обновл. · 80 DLC · 400 сжатых».

**Проверено.** `tests/LibraryIndexTest.kt` — 65 проверок, зовут сам
`LibraryIndex` (файл в тесте и в APK — один исходник), плюс сверка с
`GameHelper.kt` / `GameFolderScanner.kt` / `library.html`, чтобы правило снова
не разъехалось на две копии. Лаборатория в студии прогоняет ту же библиотеку
через настоящую страницу.

## 2. На вопрос «почему не видно» нечем было ответить

Панель показывала «нет игр» при 250 файлах в папке и не говорила почему.

**Стало.** `LivePanel.libraryReport()` + экран «почему?» на странице:

```
742 файлов · 120 игр · 120 обновл. · 80 DLC · 400 сжатых → Конвертер
папок 1 · файлов 742 · игр 120 · сжатых 400 · не прочитано 6
compressed: 400 · split: 16 · unreadable: 6
```

и строки файлов с причиной словами. Ключи при этом остаются отдельной
строкой статуса — они не причина «пустой папки» и не должны её маскировать.

## 3. Сжатый образ было нечем распаковать из библиотеки

Конвертер умел `nsz → nsp`, но требовал выбрать файл заново через системный
пикер, хотя страница уже знает путь.

**Стало.** Мост: `convertPath(uri)` → `Converter.enqueue(...)`. Кнопка
«Распаковать» на карточке ставит **этот** файл в очередь и переключает на
вкладку конвертера.

---

## 4. `lateinit var preferences` падал вне полного обхода

`GameHelper.preferences` инициализировался только в `getGames()`.
`getGame()` вызывается ещё и при добавлении одной игры (файловая кнопка) —
там `lateinit` бросал `UninitializedPropertyAccessException`.

**Стало.** Свойство с ленивой инициализацией; присваивание в `getGames()`
осталось и работает через сеттер.

---

## 5. Страница не переживала `localStorage` в песочнице

В `library.html` на верхнем уровне:

```js
let SORT = localStorage.getItem('eden-sort') || 'name';
```

В документе без storage access — sandbox-iframe, некоторые WebView с
отключённым DOM storage — это `SecurityError` до первой отрисовки: белая
страница без единой ошибки на экране.

**Стало.** В лаборатории страница получает подмену `localStorage` перед своим
скриптом (`STORAGE_SHIM`). Проверка «страница поднялась» ловит именно этот
случай. **Не исправлено в самой странице** — там правка потребует обернуть
чтение в try/catch; это отдельная небольшая задача, и я её не делал, чтобы не
менять поведение вслепую.

## Что осталось нерешённым

* **`Converter` и zstd.** На Android `SYMBIOSIS_HAS_ZSTD` включается по
  `__ANDROID__`, то есть распаковка реальных NSZ зависит от того, что
  `externals/zstd` попал в include path сборки. Проверить это без NDK нельзя;
  если распаковка отвечает «this build has no zstd decoder», дело в этом.
* **`getIsValid` на больших xci.** Заголовок читается целиком через native;
  на файле в 8 ГБ это заметно, но замеров нет.
* **Сборка APK.** Не выполнялась: `assembleLegacyDebug` требует NDK и полного
  дерева Eden (~25 минут на раннере).
* **Экран «почему?» не открывается из нативной части** (RecyclerView) — только
  из WebView-панели, которая и есть домашний экран с v20.
