# APKForge Studio · Symbiosis

**APKForge Studio** — браузерная Android-IDE, которая собирает настоящие APK
(`classes.dex`, `AndroidManifest.xml`, `resources.arsc`, подпись v1 + v2) прямо
в браузере, без бэкенда и без установки Android SDK.

**Symbiosis** — форк эмулятора Eden под ARM Mali. Его домашний экран — это
`library.html`, страница в WebView, которая получает библиотеку игр из Kotlin
через `window.Symbiosis`.

Этот репозиторий — то и другое вместе: IDE, в которую встроена лаборатория,
где **настоящая** страница Symbiosis запускается с настоящим мостом и
искусственной библиотекой на 250–750 файлов, и 13 проверок говорят, что она
показывает.

```
npm install
npm run dev        # IDE + Symbiosis Lab в правом доке
npm run test:lab   # те же проверки из командной строки, без браузера
```

## Symbiosis Lab

Правый док → вкладка **Symbiosis**. Три пресета:

* **24 игры** — 24 базовых, 24 обновления, 16 DLC, 180 сжатых, 3 нечитаемых,
  4 части разрезанного образа;
* **600 файлов** — 742 файла, размер реального дампа;
* **сжатые без игр** — библиотека, в которой нет ни одной запускаемой игры:
  ровно тот случай, из-за которого жаловались на «одну игру».

Кнопка **проверить** выполняет скрипт **внутри iframe**, в мире самой страницы,
поэтому `GAMES`, `railGames()`, `visibleGames()`, `whyNot()` и `deadAction()` —
это функции из APK, а не их копия в тесте.

13 проверок:

```
ok  страница поднялась и она тёмная
ok  видны все файлы, а не один
ok  сжатые файлы в списке, а не выброшены
ok  карусель отдаёт всю библиотеку, мёртвые помечены
ok  поиск не режет карусель (v21)
ok  фильтр «Не запускается» показывает ровно их
ok  сводка пишет, сколько сжатых
ok  «почему?» открывает разбор, а не пустоту
ok  тап по сжатому не запускает сессию
ok  у сжатого есть кнопка «Распаковать»
ok  запускаемая игра запускается
ok  обновления и DLC не выдают себя за игры
ok  ни одна строка не пустая
```

## Правки к Symbiosis

```
symbiosis/changes.patch     # git diff против текущего main
symbiosis/files/...         # те же файлы целиком
```

Применить на свежий клон:

```bash
git clone https://github.com/sj0404-collab/symbiosis
cd symbiosis
git apply /path/to/symbiosis/changes.patch
# или скопировать файлы из symbiosis/files поверх дерева
```

Затронуто восемь файлов:

| Файл | Что делает теперь |
|---|---|
| `patch/android/utils/LibraryIndex.kt` | **новый**: одно правило «что за файл и запускается ли», плюс сводка по папке |
| `patch/android/utils/GameHelper.kt` | ничего не выбрасывает молча; битый файл не обрывает обход; статистика обхода |
| `patch/android/utils/GameFolderScanner.kt` | тот же правило видимости; потолок 400 каталогов снят; бюджет 25 с |
| `patch/android/utils/LivePanel.kt` | `libraryReport()`, `runnable`/`kind` у каждой игры, сжатые в списке |
| `patch/android/fragments/LivePanelFragment.kt` | мост: `convertPath()`, `libraryReport()`; версия моста 17 |
| `docs/library.html` + `patch/android/assets/library.html` | бейджи, фильтр «Не запускается», сводка, экран «почему?», кнопка «Распаковать» |
| `tests/LibraryIndexTest.kt` | **новый**: 65 проверок, включая сверку с исходниками |

Подробности — `docs/BUGS-FOUND.md`.

## Ограничения, о которых нужно сказать вслух

* **Сборка APK не проверена.** Здесь нет ни NDK, ни Eden: правки к Symbiosis
  проверены на хосте (Kotlin-тесты + JSDOM), но `assembleLegacyDebug` и запуск
  на телефоне — за вами.
* **JSDOM — не браузер.** Он не считает CSS-переменные и раскладку; проверка
  темы поэтому смотрит объявление палитры, а не итоговый цвет.
* **Мост в лаборатории синтетический.** Он отвечает теми же JSON-структурами,
  что и настоящий, но это проверка страницы, а не Kotlin-обвязки.
* Правки сделаны поверх текущего `main` Symbiosis; `patch2/` не тронут.
